# Поисковая индексация Music & Art

Основной домен: https://artmusiclazarevskoe.ru/

## Что делает сайт

- При сборке создаёт готовый HTML главной и обеих студий из тех же React-компонентов, которые видит посетитель. Тексты, контакты, фотографии и ссылки доступны без исполнения JavaScript поисковиком. Дополнительного серверного приложения нет.
- Генерирует уникальные title, description, canonical, Open Graph, JSON-LD WebSite/WebPage/BreadcrumbList и LocalBusiness/EducationalOrganization для двух реальных студий. Источник метаданных: `src/seoPages.json`; контакты и изображения берутся из исходного контента сайта.
- Указывает основной домен в canonical, в том числе у старой копии GitHub Pages. Перенаправляет www на основной адрес на Nginx.
- Создаёт `/sitemap.xml` и `/robots.txt`; внутренний музыкальный движок и аудиофайлы исключены из обхода. Основные приложения доступны по своим страницам.
- Возвращает HTTP 404 для несуществующих URL на Amvera вместо успешной пустой страницы. GitHub Pages сохраняет прежний механизм восстановления маршрутов.

Нельзя выдумывать отзывы, рейтинги, часы работы, цены и точные координаты ради разметки. Их можно добавить после получения достоверных данных от владельца. Позиции в поиске не гарантированы; индексация и ранжирование зависят от поисковика.

## Действия владельца: Яндекс

1. Войти своим Яндекс ID на https://webmaster.yandex.ru/ и добавить `https://artmusiclazarevskoe.ru/`.
2. Выбрать подтверждение через DNS TXT. Скопировать имя и значение записи, показанные Яндексом. В REG.RU открыть DNS домена, добавить TXT, указав имя из инструкции. Если указано само корневое доменное имя, поле поддомена в REG.RU — `@`. Не заменять существующие записи Amvera.
3. После распространения DNS нажать «Проверить» в Вебмастере.
4. В разделе файлов Sitemap добавить `https://artmusiclazarevskoe.ru/sitemap.xml`.
5. Отправить главную, `/art/` и `/music/` на переобход. Указать реальный регион — Сочи/Лазаревское, если в кабинете доступна настройка региональности.

## Действия владельца: Google

1. Войти своим Google-аккаунтом на https://search.google.com/search-console/.
2. Добавить ресурс типа «Домен»: `artmusiclazarevskoe.ru` (без https и www).
3. Скопировать TXT `google-site-verification=...` из кабинета. В REG.RU добавить отдельную TXT-запись для `@` с этим значением. Сохранить TXT Amvera и Яндекса.
4. Нажать «Подтвердить» после обновления DNS.
5. В разделе Sitemap отправить `https://artmusiclazarevskoe.ru/sitemap.xml`.
6. Через проверку URL запросить индексирование главной, `/art/` и `/music/`.

Каждая система может предоставить собственную запись подтверждения. Использовать точное значение, выданное текущим кабинетом. Коды подтверждения не являются паролями; пароли и токены передавать не нужно. Записи подтверждения оставить после успешной проверки.

Перед созданием карточек проверить, нет ли существующих, чтобы не создавать дубли. Подтвердить карточки обеих студий по их реальным адресам:

- «Рыбка»: Сочи, Лазаревское, переулок Павлова, 2; +7 (988) 145-94-19; сайт https://artmusiclazarevskoe.ru/art/.
- stARTup: Сочи, Лазаревское, Социалистическая, 1; +7 (961) 506-27-73; сайт https://artmusiclazarevskoe.ru/music/.

Оформить в https://business.yandex.ru/ и https://www.google.com/business/ (доступность создания и подтверждения Google-карточек для региона определяется Google). Добавить реальные категории, расписание, услуги и фотографии. Собирать отзывы реальных посетителей без накрутки. Поддерживать совпадение адресов и телефонов на сайте и картах. При необходимости заполнить карточки в 2ГИС.

Полезные запросы: «мастер-классы Лазаревское», «рисование для детей Лазаревское», «рисование для взрослых Лазаревское», «уроки гитары Лазаревское», «уроки барабанов Лазаревское», «уроки бас-гитары Лазаревское». Не обещать первое место по этим запросам. После появления статистики смотреть реальные запросы и переходы в Вебмастере и Search Console и уточнять контент по ним.

## Проверка и публикация

Сборка Amvera: `SITE_BASE_PATH=/ SITE_URL=https://artmusiclazarevskoe.ru VITE_SITE_URL=https://artmusiclazarevskoe.ru npm run build:production`.

Предварительный рендеринг выполняется только при сборке. Временные файлы удаляются из `node_modules`, исходники и зависимости серверного рендеринга не публикуются Nginx. В готовом HTML у главной и студий есть видимый контент; у каждого маршрута — собственный canonical и JSON-LD. Sitemap не содержит выдуманного lastmod. По просьбе пользователя не запускать браузерные и автоматические тесты; проверять сборку и её HTML-артефакты.
